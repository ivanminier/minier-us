# Phase 1 audit — minier.us and trinityredistricting.com

Audit date: 6 November 2026. Auditor: Claude (AI), working in a cloud session for Ivan Minier.
Method: read both repositories, ran their builds and tests, fetched the live sites, and compared live output to the local builds.

## 1. Repositories and deployment

| | minier.us | trinityredistricting.com |
|---|---|---|
| Repository | `ivanminier/minier-us` | `ivanminier/trinity-site` |
| Stack | Astro 7, TypeScript, plain CSS, `sharp` for images | Hand-written static HTML + Node build scripts; Cloudflare Worker (`worker.js`) for Trinity AI, D1, Workers AI, cron |
| Build | `npm run build` → `dist/` (15 pages) | `npm run build:site` → `.deploy/` (build gate) |
| Tests | none in repo | `npm run check` (content, docs, facts, knowledge index) and `npm test` (98 Node tests) |
| Hosting | Cloudflare Pages (`wrangler.jsonc` `pages_build_output_dir`) | Cloudflare Workers with static assets (`wrangler.jsonc`) |
| Live vs. repo | **In sync.** Live HTML text matches the local `main` build except Cloudflare's automatic e-mail obfuscation. | **In sync.** `/build.json` reports commit `22874f4` (= `main` HEAD), release 1.3 (2026-10-29), knowledge-index hash matches. |

Results on 6 Nov 2026: minier-us build passed. trinity-site `check` passed, `test` passed 98/98, `build:site` passed, and its Python workbook verifier passed.

`tests/verify-deploy.mjs` reported one failure, "Public status hides diagnostics". **This is a false positive caused by this cloud session.** The session's network proxy attaches the owner's admin token to requests to `trinityredistricting.com`, so the API correctly returns the admin view. Re-run without the token to confirm. The live check also confirms that the saved token is valid.

## 3. Verified inconsistency (fixed in Phase 1)

`minier-us/src/data/projects.ts` → `trinityConcept` hard-coded **1,850–2,100 beds** and **1,400–1,650 net-new**. These are the superseded **Version 1.1** (May 2026) figures, as recorded in `facts.json` → `release.previous[0]`. They appeared on the live `/work/trinity-redistricting/` page.

Fix: added `scripts/sync-trinity-facts.mjs` and the generated `src/data/trinity-facts.json`. Pages now read figures through `src/data/trinity.ts`, and `npm run build` fails if the snapshot is out of date with a sibling `trinity-site` checkout. No runtime cross-domain fetch is involved.

## 4. minier.us inventory

**Routes (15):** `/`, `/work/`, `/work/{lineup, rental-record, modeboard, trinity-redistricting, uvm-laundrylink}/`, `/about/`, `/resume/`, `/contact/`, `/tideframe/`, `/ideas/`, `/ideas/{housing-as-a-system, messy-catalogs}/`, `/404`. Redirects: `/work/trinity` → `/work/trinity-redistricting` (301), plus two others.

**Components:** `Nav` (accessible mobile menu with focus trap), `Footer`, `WorkCard`, `ProjectMedia` (responsive `srcset` with size presets), `ProjectFacts`, `NextProject`, `LineupTransform`.

**Design system:** per-route "identities" set by `<Base theme>`, each with its own font pair and colour tokens. There are light and dark variants and a `prefers-reduced-motion` rule. The Trinity page uses the `editorial` identity (Literata + IBM Plex Sans, green ink, terracotta accent). Fonts are self-hosted under OFL.

**Metadata:** each page has a canonical URL and OG image. JSON-LD `ProfilePage` + `Person` is on every page, plus `CreativeWork`/`SoftwareApplication` on project pages. The sitemap comes from `@astrojs/sitemap`.

**Media:** `public/media/trinity/` holds 6 images (hero, map, Peaks, Rise, Cottages, vision) at 3 sizes plus the logo.

**Downloads:** `public/ivan-minier-resume.pdf` is a print of `/resume`.

**Links:** no broken internal references. `/404` advertises an `og:url` of `/404/`, which is harmless. External links return 200, except uvmlaundry.com, which isn't on this session's network allowlist and wasn't tested (the site already says LaundryLink is offline).

### Content issues found

1. Old Trinity figures. Fixed, see §3.
2. The case-study caption "Trinity Peaks — proposed first-year housing" disagrees with v1.3, which says first- **and second-year**.
3. Trinity renderings are captioned "Concept visualization" without saying they are **AI-assisted**. trinityredistricting.com labels the same imagery as AI-assisted.
4. The homepage gives the built environment one card out of three, and Trinity isn't mentioned in the hero. This doesn't reflect the stated career direction.
5. The work index is one flat list, with no grouping by discipline.
6. Prior undergraduate study in Business Administration and Marketing appears nowhere (supplied in the brief, institution not supplied).
7. The case study is short. It has no process, contribution breakdown, alternatives, timeline, or status section.

## 5. trinityredistricting.com inventory (summary)

- **Pages:** 22 core public pages plus 9 redirect stubs. **Documents:** 13 HTML document sources (`content/docs`), 13 accessible companions, a PDF packet (verified by `scripts/verify-pdfs.py`), memo, and a 16-slide deck. **Data:** facts, sources, capital model, documents, asset manifest. **AI:** Trinity AI 3.3 (RAG, D1 logs, live layer).
- **Video:** a May 2026 v1.1 archive, labelled as superseded.
- **Evidence posture:** strong. Every figure carries a status label, there is a source ledger, renderings are labelled AI-assisted, and the "not an official plan" disclosure is consistent.
- **No floor plans, room inventory, gross floor area, or massing test fit exist** (`peaks_beds` meaning; capital line item "Gross floor area by building: unknown"). That is the gap the design studies address.
- **Verify-deploy external links:** none return 404/410. `uvm.edu/reslife/catamount-east` returns 403 to automated clients. YouTube wasn't tested because it isn't on the allowlist.
